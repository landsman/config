# Short, and explains more

A code comment, a PR description or an explanation states the core first: what
was wrong and why the fix is right, in one sentence. Then only what a reviewer
would otherwise ask — and that question must be answered. No story of how it was
found, nothing the diff already shows, no headings for one line.

**Load the `terse-prose` skill** before writing a comment, a PR body, an error
message or release notes; it has the cuts and a before/after.
